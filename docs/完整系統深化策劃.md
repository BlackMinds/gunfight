# 完整系統深化策劃

## 1. 版本目標與邊界

本批次把遠期總策劃中仍停留在目錄層的六組系統收斂為目前版本可執行內容：五個怪物陣營、完整精英詞綴、武器深度成長、角色防禦屬性、Boss 補充機制，以及帳號制非同步多人賽季。

- 正式主線上限維持第 10000 關，不新增 R6。
- 不加入付費貨幣、抽卡付費或戰力販售。
- 「多人賽季」指伺服器活動日曆、帳號成績提交與跨玩家排行榜，不包含即時連線戰鬥。
- 排名成績由伺服器讀取已驗證的雲端存檔，不接受客戶端直接提交任意分數。

## 2. 五個怪物陣營

| 陣營 | 主要階段 | 抗性與弱點 | 三人以上組合規則 |
| --- | --- | --- | --- |
| 暴徒 | 1～500 | 爆炸傷害 +10% | 群聚：移速 +8% |
| 傭兵 | 501～2000 | 物理減傷 8%，能量傷害 +8% | 編隊：行動速率 +10% |
| 機械軍團 | 2001～5000 | 物理減傷 15%，電擊傷害 +20%，毒素傷害 -50% | 方陣：受到傷害 -10% |
| 變異體 | 5001～7500 | 毒素減傷 25%，火焰傷害 +15% | 狂潮：低生命時行動速率 +15% |
| 黑域部隊 | 7501～10000 | 能量減傷 20%，物理傷害 +5%，狀態時間 -25% | 共振：技能與攻擊間隔 -12% |

陣營必須進入敵人實體、預覽、畫布標記、傷害結算與遙測；不能只作為名稱標籤。

| 反傷 | 2001 | 反射實際傷害的 6%，每次最多玩家最大生命 3% | 紅色反向箭頭，改用控制與續航 |

## 4. 武器深度成長

### 4.1 隨機詞綴

每把武器保存 2 條隨機詞綴；突破後解鎖第 3 條。詞綴池包含傷害、射速、暴擊率、暴擊傷害、彈匣、換彈、穿透與狀態機率。詞綴跟隨武器進度存檔並實際修改戰鬥屬性。

### 4.2 突破與重鑄

- 120 級、5 星武器可消耗 2 能量核心與 12 精密元件突破。
- 突破提供 15% 傷害、10% 射速並解鎖第 3 詞綴。
- 重鑄消耗 2 重鑄晶片，重新產生全部武器詞綴；資源不足不得部分扣除。

### 4.3 武器箱與副武器

- 戰區商店新增武器箱；開箱只從玩家等級已解鎖武器中選取。
- 開到武器時增加該武器核心並重鑄其隨機詞綴。
- 基地可指定一把不同於主武器的支援武器；支援武器每 2.5 秒自動攻擊一次，使用 35% 面板傷害，不消耗主武器彈藥。

## 5. 角色防禦屬性

| 屬性 | 來源與作用 |
| --- | --- |
| 防禦 | 等級、天賦與裝備；按 `100 / (100 + 防禦)` 降低生命傷害 |
| 護甲 | 每次部署恢復；先於生命承受傷害，Boss 穿透 20% 護甲 |
| 幸運 | 等級、後勤天賦與裝備；提高掉落觸發率與高品質權重，上限 60 |

HUD 與基地預覽必須顯示三項數值；傷害浮字區分護甲吸收與生命傷害。

## 6. Boss 補充機制

- 圓形彈幕：大 Boss、階段 Boss 與終局 Boss 在技能循環中發射 12 向彈幕。
- 狂暴階段：生命低於 15% 後只觸發一次，行動速率提高 25%、接觸與投射物傷害提高 20%。
- 短暫弱點：完成技能後暴露 2.5 秒；命中弱點造成 35% 額外傷害，畫布與 Boss HUD 同步提示。

## 7. 帳號制非同步多人賽季

### 7.1 伺服器活動日曆

- 伺服器以 UTC 時間決定目前賽季與每週活動，不依賴客戶端時鐘。
- API 回傳當前賽季、開始/結束時間、當週活動與下一活動。

### 7.2 成績提交與排行榜

- 登入玩家可觸發「同步賽季成績」。
- 伺服器從該玩家最新有效雲存檔提取最高主線、最快懸賞、生存擊殺和活動積分，再以單調規則更新賽季成績。
- 排行榜支援最高主線、最快懸賞、生存擊殺、活動積分四種指標；回傳前 50 名與目前玩家名次。
- 未登入、沒有有效雲存檔或資料庫異常時顯示明確錯誤，不回傳偽造玩家。

## 8. 存檔與相容

- 存檔版本提升至 9。
- 舊存檔的武器詞綴、突破、武器核心、副武器使用安全預設值。
- 新欄位在本地、雲端 payload 驗證和衝突流程中保持相容。
- 排行榜資料與雲存檔分表；刪除帳號時級聯移除賽季成績。

## 10. 排行榜可信閉環與裝備補完規格（2026-07-23）

### 10.1 排位行動票據

- 登入玩家開始主線、挑戰、懸賞、生存或活動行動時，由伺服器簽發一次性行動記錄，固定帳號、賽季、活動、模式、關卡與伺服器開始時間。
- 結算只接受仍在有效期內且尚未完成的記錄；同一記錄重複提交、跨帳號提交、模式或關卡不一致均拒絕。
- 每個帳號同時只保留一張有效票據；開始新排位行動會使先前未完成票據失效。
- 懸賞時間使用伺服器開始/完成時間；活動積分由伺服器按首通與當週加成計算；主線以獨立 `gunfight_ranked_progress` 連續推進；非生存行動必須提交完整理論擊殺數，生存擊殺不得超過十段壓力波次的理論總量。
- 排行榜只聚合已完成的排位行動，不再從雲存檔中的 `season`、`highestCleared` 等客戶端欄位直接取分。
- 此閉環防止修改雲存檔直接刷榜、偽造任意分數與重複結算；目前仍是伺服器票據與規則校驗，不宣稱已完成輸入逐幀重播或全量伺服器戰鬥模擬。

### 10.2 賽季與活動

- 本地賽季狀態保存伺服器賽季 ID；讀到新賽季時重置積分、活動完成、懸賞最快與生存最高擊殺，不影響主線、裝備和資源。
- 聯網排行按 `season_id` 隔離，上一賽季成績不得寫入新賽季。
- 懸賞增援週提供榮譽幣 `+25%`；生存前線週提供賽季積分 `+25%`；戰區突襲週額外提供精密元件 `+1`；首領獵殺週額外提供精密元件 `+1`。
- 聯網排行加成以伺服器簽發票據時的活動為準；離線本地遊戲可以繼續，但不產生可同步的排位成績。

### 10.3 武器與角色屬性補完

- 武器隨機詞綴池補入「暴擊傷害」，與既有七類詞綴共同進入生成、重鑄、存檔、預覽與實際暴擊計算。
- 戰區商店武器箱具有有限庫存；購買後從已解鎖武器中抽取，增加該武器核心並立即重鑄 2／3 條隨機詞綴。
- 配件主副詞條補入防禦、護甲與幸運。防禦只由等級、天賦與實際裝備數值提供；護甲詞條提高部署護甲上限；幸運詞條直接提高掉落率與品質權重，不再借用經驗詞條。
- 遠期裝備第 6～13 章的全部具名配件進入掉落池；其簡單效果使用現有主副詞條，特殊模組使用可測試的機制鍵，不允許只保留名稱。

## 11. 可信排行上線前收口規格（2026-07-26）

### 11.1 資料遷移與舊帳號規則

- 本輪沒有正式線上玩家或已確認可繼承的可信排位資料，因此正式遷移採「乾淨賽季」規則：`gunfight_users` 與 `gunfight_cloud_saves` 原樣保留，所有帳號的 `gunfight_ranked_progress.highest_stage` 從 `0` 開始。
- 不從雲存檔的 `highestCleared`、本地 `season`、歷史 `gunfight_season_scores` 或任何客戶端欄位回填可信排位進度；這些資料缺少一次性票據與服務端結算證據。
- 首次執行正式遷移時清空尚未上線的排位票據與賽季榜測試資料，再為所有既有帳號補入進度 `0`。遷移版本必須留有唯一記錄，重跑不得再次清空已上線後產生的可信成績。
- 如果日後確認已存在正式線上玩家，不得直接沿用本規則；必須先凍結寫入、匯出五張業務表、由負責人批准逐帳號白名單，再另立遷移版本。

### 11.2 戰前票據與降級語義

- 已登入玩家按下部署後，介面先進入「正在取得排位票據」狀態；票據成功前不得切換到戰鬥模式、啟動計時或生成敵人。
- 開票成功後才開始戰鬥，票據固定帳號、賽季、活動、模式與關卡。未登入玩家直接開始本地行動。
- 開票逾時、401、409、503 或其他失敗不阻斷遊戲；介面必須在進入戰鬥前明確顯示「本地行動，不計入排行榜」及失敗原因，本局不得在稍後補票或把本地結果同步成排位成績。
- 同一帳號的開票交易必須串行。並發請求可先後成功，但資料庫最終只能保留最後簽發的一張有效票據；較早票據立即失效，且不得因唯一索引競爭誤報 503。
- 重複點擊部署時只允許一個開票請求在途，避免玩家無意替換剛取得的票據。

### 11.3 結算、賽季與活動邊界

- 完成 API 必須以「票據 ID + JWT 帳號 + active 狀態」共同鎖定結算對象；同票據重複結算與跨帳號結算均拒絕，且不得改變進度或榜單。
- 新票據替換舊票據後，舊票據只能得到「不存在或已結算」類業務拒絕；新票據可正常結算。
- 票據簽發後即固定 `season_id` 與 `activity_id`。即使自然時間跨入新賽季，結算也只能寫回票據所屬舊賽季，不得污染新賽季榜單；新開票則使用新賽季。
- 活動加成只讀取票據上的 `activity_id`，不按結算時當週活動重算；活動首通次數只統計同帳號、同賽季已完成的活動票據。
- 排位完成、連續進度與賽季榜更新必須位於同一資料庫語句／交易中。資料庫中斷或恢復期間要麼全部成功，要麼全部不生效；恢復後未被消費且未過期的票據仍可重試。

### 11.4 遷移與回滾策略

- 正式升級腳本為 `server/database/migrations/20260726_trusted_ranked_up.sql`，在交易與遷移鎖內建立／核對 `gunfight_users`、`gunfight_cloud_saves`、`gunfight_season_scores`、`gunfight_ranked_progress`、`gunfight_ranked_runs`，並執行一次性的乾淨賽季初始化。
- 部署前先建立 Neon 可恢復分支／時間點並匯出五張業務表的列數與約束摘要；遷移後逐表核對外鍵、檢查約束、索引與既有帳號的 `0` 進度。
- 應用回滾優先部署上一個健康 Vercel 版本，執行 `20260726_trusted_ranked_rollback.sql` 使所有在途票據失效，但保留五張表和已完成成績供稽核；不得在事故處理中直接刪除帳號或雲存檔。
- 若需回退資料或結構，使用部署前 Neon 恢復點建立獨立恢復分支，核對五張表後再切換連線；禁止在 Production 直接執行 `DROP TABLE`。切回前先停止寫入，切回後重新登入並做最小讀寫驗證。
